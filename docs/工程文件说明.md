# 工程文件说明

本仓库里的工程是「造世界编辑器」的本地工程目录，结构固定为：

```
projects/project_vqo1bvzh/
├─ scene.data    6,082,576 B   地图本体（ZIP）
├─ project.json             149 B    工程名与封面
├─ world-config.json        ~1.4 KB  worldId / worldType
├─ settings/env-param-overrides.json  环境光覆盖
└─ scripts/client/index.lua  44 B    场景脚本入口
```

## 1. 五个文件的职责

| 文件 | 谁在改 | 说明 |
|-|-|-|
| `scene.data` | 编辑器 | 唯一不可替代的资产。ZIP 容器，内含高度图、6 层 SplatMap、俯视覆盖图、PCG 参数 |
| `project.json` | 编辑器 / 人 | `name`（项目列表显示名）、`cover`（封面资源 key）、`creator.version` |
| `world-config.json` | 编辑器 | `worldId`、`worldType: avatar`。原包里的 `quickPreview` 段（二维码 + 时间戳）已移除，编辑器首次打开会自动重建 |
| `settings/env-param-overrides.json` | 编辑器 | 环境光等参数的覆盖值 |
| `scripts/client/index.lua` | 人 / agent | 场景脚本入口，目前只有一行 `require("main")` 之类的引导 |

编辑器打开工程时，还会在这个目录里**自己生成**：`.creator/`、`ai-asset-generate-config.json`、`ai-pcg-generate-config.json`、`ai-topology-generate-config.json`。这些不属于资产，已在 `.gitignore` 中屏蔽。

| 条目 | 原始大小 | 说明 |
|-|-|-|
| `HeightMap_-2082996523.data` | 264,196 B | 257 × 257 高度图，float32 小端 |
| `SplatMap_-2082996523_0.png` | 368 B | 地表材质第 1 层权重，L 通道 PNG |
| `SplatMap_-2082996523_1.png` | 368 B | 第 2 层 |
| `SplatMap_-2082996523_2.png` | 6,048 B | 第 3 层（Road 变体） |
| `SplatMap_-2082996523_3.png` | 764 B | 第 4 层 |
| `SplatMap_-2082996523_4.png` | 5,761 B | 第 5 层 |
| `SplatMap_-2082996523_5.png` | 440 B | 第 6 层 |
| `MatCoverTex_-2082996523.png` | 6,040,526 B | 2048 × 2048 RGBA 俯视覆盖图（**占了整个文件 94% 的体积**） |
| `SerializePcgData.json` | 73,824 B | 场景参数：出生点、节点变换、音频、导航等 |

解压后合计 6,392,295 B，压缩包 6,082,576 B —— 压缩率极低，因为大头是一张已压缩的 PNG。**这就是为什么每次保存都会产生一个完整的新 6 MB blob。**

### 绝对不能动的部分

`SerializePcgData.json` 里的 `resourceRefs` 是按**条目名**引用上面这些文件的：

```json
{ "refId": 0, "audioType": 20, "volume": 100,
  "uri": "hamlet-ugc/chengyunchuming_1.wav" }
```

所以：不要重命名条目、不要重新打包、不要用别的工具「优化」这个 ZIP。一旦名字变了，编辑器加载时会直接报资源缺失。

## 3. 地形与节点参数

| 项 | 值 |
|-|-|
| 地形尺寸 | 64 m × 64 m（单块 `TerrainTile`） |
| 高度范围 | 归一化 0.00 – 0.12 |
| 材质层 | 6 层（Grasslands / Plain / Road 的 H、V 变体） |
| 场景节点数 | 6 |
| 出生点 | `BornPoint` id `-226777587`，世界坐标 `(119.7, 80.0, 88.6)` |
| `respawnHeightY` | `-50.0` |

节点树：

| id | 类型 | 名称 | 父 |
|-|-|-|-|
| -461733601 | Map | 地图 | 根 |
| 28179375 | Terrain | 地形 | 地图 |
| 1617895547 | DisableEdit | 湖泊 | 地形 |
| 1678445172 | TerrainTile | 地形块(0,0) | 地形 |
| -2082996523 | TerrainTile | 地形块 | 地形块(0,0) |
| -226777587 | BornPoint | 出生点 | 根 |

**已知缺陷**：出生点在 `(119.7, 80.0, 88.6)`，已超出 64×64 地形块范围。预览时角色可能悬空或直接掉落。修法二选一：在编辑器里把 `BornPoint` 拖到南端主街上，或调大 `SerializePcgData.json` 里的 `respawnHeightY`。

## 4. 唯一的云端依赖

场景音频 `hamlet-ugc/chengyunchuming_1.wav` 走 CDN，不在本仓库、也不在编辑器素材缓存里。缺失时表现为**没有环境音**，不影响地形、材质、碰撞加载。

如果要做完全离线的分发包，需要在编辑器里把这段 BGM 换成本地文件，或删掉该音频引用后重新导出 `scene.data`。

## 5. 体积策略

- 单文件 6 MB，远低于 GitHub 100 MB 硬限制，因此**首版不启用 Git LFS**，降低成员安装门槛。
- 代价：每次保存 `scene.data` 都会在 git 历史里新增一个完整 blob。大致算一下，改 30 次 ≈ 180 MB 仓库。
- 何时该动：仓库超过约 300 MB 时，考虑 `git lfs migrate import --include="*.data"`，或另起一个干净仓库保留最终版。迁移前务必通知所有成员重新 clone。
