# 同步与协作规范

## 1. 为什么不能"打开 clone 出来的文件夹"就完事

造世界编辑器**不扫描文件系统**。它只认一个登记表：

```
<数据目录>/projects/projects.json      ← 数组，每条一个工程
```

单条记录长这样：

```json
{
  "projectPath": "C:\\Users\\pxc\\AppData\\Roaming\\AI World Creator\\projects\\project_vqo1bvzh",
  "latestOpenTime": 1793588010516,
  "latestEditTime": 1793588010516,
  "uid": "2349009045037543"
}
```

关键点：

- `projectPath` 是**绝对路径**，指到哪编辑器就去哪读工程 —— 并不强制在 `%APPDATA%` 下。
- `uid` 是**当前登录账号**的 uid。填错不会立刻报错，但工程会挂到别人名下。
- 这个文件里含本机账号信息，**永远不进仓库**。

所以 clone 到任意目录都行，只要"登记"一次。

## 2. 三种装法

| | `install`（复制） | `link`（登记） | `sync`（覆盖） |
|-|-|-|-|
| 命令 | `world.py install` | `world.py link` | `world.py sync` |
| 工程文件在哪 | `%APPDATA%\...\projects\project_vqo1bvzh` | 你的 clone 目录 | 已登记的那个路径 |
| git 工作区 = 工程？ | 否 | **是** | 否 |
| 适合谁 | 只想打开看看、不熟悉 git | 要改图并提交的人 | 已装过、`git pull` 之后更新 |
| 改动怎么回到仓库 | 要手动拷回 clone 目录再 commit | 直接 `git commit` | 不涉及（只下行） |
| 已有同名工程时 | 改名备份为 `project_vqo1bvzh.bak-<时间戳>`，再复制 | 只动 `projects.json`（先备份） | 逐文件备份为 `*.bak-<时间戳>` 后覆盖 |

`install` 和 `link` 都是**幂等**的：重复执行不会在 `projects.json` 里留下重复记录（按 `projectPath` 去重后重新追加）。

## 3. uid 从哪来（老脚本的坑）

`tools/world.py` 的取值顺序：

1. `--uid` 命令行参数
2. `<数据目录同级>/造世界编辑器/config.json` → `userinfo.uid`（**最可靠**，就是编辑器当前登录的账号）
3. 已有 `projects.json` 首条记录的 `uid`
4. 都拿不到 → **报错退出**

老的 `tools/install-windows.ps1` 在第 3 步为空时，会回退到硬编码的 `3309980302973310` —— 那是打包者的 uid。结果就是工程在你机器上登记到了别人的账号名下。**不要再用那个脚本做首次安装**，它只作为兼容保留。

## 4. 日常协作流

角色：**编辑者**（唯一有权改 `scene.data` 的人）与**消费者**（只 pull 不发版）。

### 编辑者

```bash
git clone https://github.com/MAChine110p/DY-AI_TOWN.git
cd DY-AI_TOWN
python tools/world.py link          # 只做一次
# —— 在编辑器里改图，保存 ——
python tools/world.py verify --update-manifest
git add -A && git commit -m "[asset] 把南侧广场铺装换成糖果砖"
git push
```

### 消费者

```bash
git clone https://github.com/MAChine110p/DY-AI_TOWN.git
cd DY-AI_TOWN
python tools/world.py install       # 只做一次
# 之后每次更新：
git pull && python tools/world.py sync
```

`sync` 只覆盖 5 个资产条目（`project.json` / `scene.data` / `world-config.json` / `settings/` / `scripts/`），`.creator/`、`ai-*-config.json` 这些运行时产物原样保留。**执行 sync 前请先在编辑器里关掉该工程**，否则编辑器退出时可能用内存里的旧数据写回，把同步覆盖掉。

## 5. 二进制冲突怎么处理

`scene.data` 是 ZIP，git 无法合并，冲突时只会得到：

```
warning: Cannot merge binary files: projects/project_vqo1bvzh/scene.data (HEAD vs. <commit>)
CONFLICT (content): Merge conflict in projects/project_vqo1bvzh/scene.data
```

处置：

1. 不要试图合并字节。选一方：
   `git checkout --ours projects/project_vqo1bvzh/scene.data`（保留自己的）
   或 `git checkout --theirs ...`（用对方的）
2. 在编辑器里打开确认能正常加载（重点看地形是否完整、出生点是否正常）
3. `python tools/world.py verify --update-manifest` 刷新清单
4. 提交时在 commit message 里写明"以 X 方版本为准，Y 方改动待重做"

**预防**：同一张图同一时间只允许一个编辑者。要并行就在编辑器里另建工程（不同 worldId），最后再合并场景。这是工具层面无法自动解决的，只能靠纪律。

## 6. 备份与回滚

- 所有写 `projects.json` 的操作都会先存 `projects.json.bak-<时间戳>`
- `install` 覆盖工程前会把旧目录改名 `project_vqo1bvzh.bak-<时间戳>`
- `sync` 覆盖单文件前会把旧文件存 `文件名.bak-<时间戳>`
- 回滚资产：`git log --oneline -- projects/project_vqo1bvzh/scene.data` 找到上一个版本，`git checkout <sha> -- projects/project_vqo1bvzh/scene.data`，再 `sync` 到编辑器目录

## 7. 常见报错对照

| 现象 | 原因 | 处理 |
|-|-|-|
| 编辑器项目列表里没有这个工程 | 没登记 / 登记了别的账号 / 工程路径不存在 | 重跑 `python tools/world.py install`，确认 `projects.json` 里 `uid` 是你自己的 |
| CI 红：`sha256` 不一致 | 改了文件没刷清单 | `verify --update-manifest` 后一起提交 |
| CI 红：`hygiene` | 提交了 `projects.json` / `.bak-*` / `.creator/` | `git rm --cached <path>`，确认 `.gitignore` 生效后重提交 |
| 编辑器提示"场景升级失败" | 工程是 1.0.92 导出，编辑器版本更低 | 升级编辑器，不要把工程"降级保存" |
| 打开后角色悬空 / 掉下去 | 出生点在地形块外 | 见 `docs/工程文件说明.md` 第 3 节 |
| 没有环境音 | 音频走 CDN，离线或 CDN 不通 | 正常现象，不影响地形 |
